# 多國語言（i18n）規則

## 機制

- 程式碼裡的原文是**繁體中文（台灣）**，原文本身就是查表的鍵：`Loc.T("設定…")`。沒有翻譯時直接顯示原文。
- 英文是樞紐語言（`ThumbDock/Lang/en.json`，扁平的 `"原文": "英文"`），譯者從英文翻。其他語言是格式 2 的 JSON（每條 `{ "text", "en", "note" }`，`en` 是翻譯當時的英文，用來偵測過時），格式與工具見 `docs/i18n-translation-format.md`。
- `ThumbDock/Lang/*.json` 全部內嵌進 exe（出貨語言）；`config/lang/*.json` 給使用者新增語言或逐鍵覆蓋內嵌的語言。缺少的鍵退回英文，再退回原文。載入時會驗證佔位符，壞掉的條目丟棄並在設定視窗顯示警告（`Loc.Warnings`）。
- 語言選擇存在 `config/language.txt`（內容 `auto` 或語言代碼）。`auto` 跟隨 Windows 顯示語言：繁體中文用原文，有對應語言檔就用，否則英文。更改後重新啟動才生效。
- 不支援右到左（RTL）語言（阿拉伯語、希伯來語等），2026-11-09 定案。

## 寫程式時

1. 使用者看得到的文字一律 `Loc.T(...)`：視窗標題、按鈕、功能表、對話窗、通知（`Notify`）、標籤、工具提示、命令列說明。
2. **一個 `Loc.T` 只放一個字串常值**，不可用 `+` 串接、不可用 `$"..."`。需要變數時用 `{0}`、`{1}` 佔位：`Loc.T("佈局「{0}」正被使用。", name)`。長文用 `\n`、`\r\n` 寫在同一個常值內。
3. 不翻譯：記錄檔（`AppLog`）訊息、例外訊息、程式內部識別碼、存進檔案或用來比對的字串（例如保留佈局名稱「預設」`DefaultLayouts.ReservedName`、佈局檔欄位值）。如果同一個字串既是顯示用又是識別碼，識別碼維持原樣，顯示處再 `Loc.T`。
4. `const`、`static readonly` 欄位不能呼叫 `Loc.T`（類別載入時語言可能還沒就緒）：改成屬性或方法，使用時才呼叫。
5. 新增或修改原文時，必須同步更新 `ThumbDock/Lang/en.json` 的鍵（單元測試 `LocalizationTests` 會檢查：原始碼用到的每個鍵都有英文、英文沒有多餘的鍵、佔位符 `{n}` 一致）。

## 新增或更新一個語言（維護者）

用 `tools/LangTool`（詳見 `docs/i18n-translation-format.md` 第 4 節）：

```powershell
$dn = "$env:LOCALAPPDATA\Microsoft\dotnet\dotnet.exe"
& $dn run --project tools/LangTool -- new ja --name 日本語 --status "機械翻訳の初稿"
& $dn run --project tools/LangTool -- export ja            # ThumbDock-ja-<日期>.csv 交給譯者（Excel 可直接開）
& $dn run --project tools/LangTool -- import ja ThumbDock-ja-<日期>.csv
& $dn run --project tools/LangTool -- check                # 建置前驗證；單元測試也會驗每個內嵌語言檔
& $dn run --project tools/LangTool -- status               # 原文改過之後看哪些條目需覆核，再 export ja --pending
```

- `status` 請誠實標示，例如「機器翻譯，未經母語者審閱」，用該語言寫。
- 譯文裡的 `{0}`、`{1}` 佔位符要原樣保留，語序可以調整；多出或編號超出英文範圍的佔位符會被 `import` 拒絕、被程式丟棄。
- 放在 `ThumbDock/Lang/` 的檔案建置後就內嵌進 exe，設定視窗的「語言」下拉會出現它。

## 使用者自行新增或修正語言

把格式 2 的 JSON 放到 exe 旁的 `config/lang/<代碼>.json`：同代碼的檔案會逐鍵覆蓋內嵌版本（只放要改的幾條即可），新代碼就是新語言。0.10.x 的扁平格式 `"原文": "譯文"` 仍可讀。
