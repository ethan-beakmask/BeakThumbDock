# 起動設定ファイル（起動時のプログラム起動）

レイアウトごとに、開くプログラムを列挙した起動設定ファイルを 1 つ持てます。ThumbDock は起動後にそれらを順番に実行し、現れたウィンドウを指定のスロットに割り当てます。

この文書は機械翻訳をもとにした初稿で、ネイティブによる確認を受けていません。

他の言語：[繁體中文](launch-config.md) | [English](launch-config.en.md)

## 有効にする

1. タスクトレイアイコン →「設定…」→「起動時に ThumbDock が起動設定ファイルのプログラムを起動することを許可」にチェックを付けます（**既定はオフ**）。
2. 「ウィンドウ選択」→「起動時に実行」→「起動設定ファイルを編集…」でフォームが開きます。JSON を直接編集したい場合は、フォーム内の「メモ帳で編集（上級者向け）…」を押すと、ひな形が作られてメモ帳で開きます。
3. 保存します。以後：
   - ThumbDock の起動時に、現在のレイアウトの設定ファイルが実行されます。
   - 手動の場合：「ウィンドウ選択」→「起動時に実行」→「このレイアウトのプログラムを今すぐ起動」。
4. コマンドライン引数 `--no-launch` で強制的に無効にできます。設定より優先されます。

ファイルの場所：`config\launch\<レイアウト名>.json`。

### 作業モードの切り替え

1 つの作業モード（事務、開発、監視など）が 1 つのレイアウトで、それぞれに起動設定ファイルがあります。設定で「レイアウト切り替え時に、そのレイアウトの起動設定ファイルでプログラムも準備する」にチェックを付けると（既定はオフ。「許可」も有効にする必要があります）、メニューからレイアウトを切り替えたときに次のように動作します。

1. まず新しいレイアウトを読み込み、**すでに開いている**ウィンドウを自動割り当てでスロットに戻します。
2. 次に、**まだウィンドウのない**スロットの項目だけを起動します。開いているプログラムを重複して開くことはなく、**前のレイアウトのプログラムを閉じることもありません**。
3. 設定ファイルのないレイアウト、または設定ファイルに書かれていないスロットについては、何も起動しません。

開いているプログラムを新しいレイアウトが認識するには、スロットに一致ルールが必要です。ルールは、起動によって初めてウィンドウが割り当てられたときに自動的に作られ、レイアウトに保存されます。

## 編集フォーム

左側は項目の一覧です（並び順が起動順。追加、複製、削除、上へ、下へ）。右側には「プログラムの種類」に応じた欄が表示され、一番下に実際のパスと引数がリアルタイムで表示されます。

| プログラムの種類 | 欄 |
|---|---|
| Chrome／Edge | プロファイル（ブラウザーの Local State から読み取ったドロップダウン。読み取れない場合は手入力）、URL、2 つの遮蔽対策フラグのチェック、その他のフラグ |
| コマンド プロンプト (CMD) | モード（`/k` 開いたままにする、`/c` 実行後に閉じる）、コマンド |
| プログラム／ショートカット／バッチファイル | 引数 |

共通の欄：スロット、プログラムのパス（参照可）、作業フォルダー、項目完了後の待ち時間（ミリ秒）、ウィンドウを待つ秒数、ウィンドウ一致ルール、メモ、「この項目をテスト」（プログラムを起動するだけで、スロットへの割り当ては行いません）。

- 「プログラムの種類」はファイルに保存されません。開くときに `path` と `args` から判定します。認識できない形式（Brave や `cmd.exe /d /k` など）は一般のプログラムとして扱われ、引数欄だけになります。
- **保存すると JSON 全体が書き直されます。** 手書きの `//` コメントは消えます。元のファイルは先に `<レイアウト>.json.bak` にコピーされます。残したいコメントは各項目の `note`（メモ）欄に書いてください。
- 同じスロットが重複している場合や、プログラムのパスが空の場合は保存できません。スロット番号がレイアウトのスロット数を超えている場合や、タイトルの Regex が無効な場合は警告だけが出ます。

## 形式

```json
{
  "launch": [
    {
      "slot": 1,
      "path": "C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe",
      "args": "--profile-directory=\"Profile 3\" https://example.com",
      "workDir": "",
      "delayMs": 1500,
      "waitSec": 15,
      "match": { "process": "chrome.exe", "titleRegex": "ウィンドウタイトルの一部" }
    },
    {
      "slot": 2,
      "path": "cmd.exe",
      "args": "/k cd /d D:\\work && python run.py"
    }
  ]
}
```

| フィールド | 必須 | 説明 |
|---|---|---|
| `slot` | はい | スロット番号（1 から）。1 つのスロットに 1 項目だけ。重複した項目はスキップされます |
| `path` | はい | プログラム、ショートカット（.lnk）、またはバッチファイル。`%ProgramFiles%` などの環境変数や、PATH 上の名前（`cmd.exe` など）も使えます |
| `args` | いいえ | 引数 |
| `workDir` | いいえ | 作業フォルダー |
| `delayMs` | いいえ | この項目の後、次を起動するまでの待ち時間。既定 1000、上限 60000 |
| `waitSec` | いいえ | プログラムのウィンドウが現れるのを待つ秒数。既定 15、範囲 1～120 |
| `match` | いいえ | 一致ルール（`process`、`class`、`titleRegex`）。下記参照 |
| `note` | いいえ | メモ。実行時は無視され、フォームで保存しても保持されます |

JSON の注意点：

- **パスの円記号（バックスラッシュ）は 2 つ重ねて書きます**（`C:\\Program Files\\...`）。引数の中の二重引用符は `\"` と書きます。誤りがあると行番号が表示されます。
- `//` コメントと、最後の項目の後ろのコンマは使えます。

## ウィンドウがスロットに割り当てられる仕組み

| `match` の有無 | 動作 |
|---|---|
| なし（既定） | 起動前に既存のウィンドウを記録し、起動後に**最初に現れた新しいウィンドウ**をスロットに割り当てます（プロセス名が `path` と同じものを優先）。ルールは自動的に作られ、レイアウトに保存されます |
| あり | 先にルールをそのスロットに書き込み、ルールに一致するウィンドウが現れるのを待ちます |

`match` を書くべき場面：同じプログラムを同時にいくつも起動する場合（複数の Chrome アカウントなど）は、最初の新しいウィンドウが目的のものとは限りません。他のプログラムがたまたま同時にウィンドウを開く場合も同様です。実際のタイトルは「ウィンドウ選択」で確認できます。

## 他の仮想デスクトップにある、または隠れているブラウザーが描画を止める

Chromium 系のブラウザー（Chrome、Edge、Brave など）にはウィンドウの遮蔽検出があり、他の仮想デスクトップにあるウィンドウや、他のウィンドウに完全に隠れたウィンドウは描画を止めます。そのためサムネイルが止まったり黒くなったりします。

次の項目はテストで**有効**でした（Chrome。他の仮想デスクトップの動画が再生され続けます）。

```json
{
  "slot": 3,
  "path": "C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe",
  "args": "--disable-features=CalculateNativeWinOcclusion --profile-directory=\"Profile 10\" https://www.youtube.com/",
  "match": { "process": "chrome.exe", "titleRegex": "YouTube" }
}
```

- どちらのフラグでも有効です：`--disable-features=CalculateNativeWinOcclusion` または `--disable-backgrounding-occluded-windows`。シークレットモードや拡張機能の無効化では変わりません。
- フラグが必要なのは**最初に起動した Chrome プロセス**だけです。同じユーザーデータフォルダーで、後から別の `--profile-directory` で開いたウィンドウにも引き継がれます。逆に、Chrome がすでに実行中（バックグラウンドプロセスを含む）の場合、後から付けたフラグは無視されます。フラグ付きの項目を最初に置くか、事前にすべての chrome.exe を終了してください。
- 確認するには PowerShell で次を実行し、メインプロセスのコマンドラインにフラグが表示されることを確かめます：`Get-CimInstance Win32_Process -Filter "Name='chrome.exe'" | ? {$_.CommandLine -notmatch '--type='} | select ProcessId,CommandLine`
- 別の `--user-data-dir` は不要です。それでも動作しますが、まったく新しいプロファイルになるため、アカウントの選択は出ず、ブックマークもなく、ログインし直す必要があります。
- これらのフラグはコミュニティで報告された回避策で、**Chromium の公式ドキュメントには記載がなく**、将来のブラウザーの更新で効かなくなる可能性があります。遮蔽検出を無効にすると CPU と電力の消費が増えます。
- Brave ではテストでこれらのフラグは**効きませんでした**。サムネイルは黒くなります。

アカウントごとに Chrome ウィンドウを 1 つ開くひな形は [launch-sample-chrome-9accounts.json](launch-sample-chrome-9accounts.json) にあります。

## 動作と制限

- スロットにすでにウィンドウがある場合（ルールで割り当てられた直後を含む）、その項目は**起動されません**。重複して開くのを防ぐためです。
- プログラムは現在のユーザーとして起動され、権限の昇格は行いません。設定ファイルにパスワードを書かないでください。
- CMD：`cmd.exe` に `/k コマンド`（実行後も開いたまま）を組み合わせます。Windows 11 では CMD のウィンドウが `WindowsTerminal.exe` によって表示されることがありますが、これは正常で、割り当てはウィンドウを基準に行われます。
- Store／UWP アプリには対応していません。
- 起動のたびに `logs\thumbdock.log` に記録されます（パス、引数、割り当て結果、タイムアウト）。問題を報告するときに添付してください。
- 存在しないスロットを指定した項目（例：スロットが 4 個しかないのに `slot: 6`）はスキップされ、ログに記録されます。先に設定でスロット数を変更してください。
